# SprintOps vision

SprintOps (working name) is a standalone app with a nice UI for the parts of Azure DevOps I use every day. It is a thin client: it talks directly to the Azure DevOps API, and Azure DevOps stays the source of truth.

## Why

I'm frustrated with the Azure DevOps UI.

## Who it's for

Me, for now. If other people are enthusiastic, it would be nice if they could use it eventually, but that is not needed now.

## What it covers

| Area | Today |
|---|---|
| Delivery plan | It annoys me |
| Editing stories | The edit dialog annoys me |
| Backlog with its three layers | I work in it a lot, and it annoys me |
| Sprint board and sprint backlog | Needs covering |
| Sprint capacity | Needs covering |
| Sprint burndown trend | Needs covering |

## Build order

1. The backlog with its three layers. From there I can organize items.
2. Editing items.
3. The other areas.

## What it doesn't cover

- The rest of Azure DevOps, because I don't use it.
- A cross-team view. It is not needed.
- Keyboard-first design. It is not a focus.

## Open questions

- What exactly annoys me in each area? They all annoy me, and the specifics should be written down from real use.
- With the cross-team view gone, what should the delivery plan do that Azure DevOps doesn't?
